## Compilación automática (GitHub Actions)

Archivo: `.github/workflows/build-web.yml`. Se ejecuta en cada push a una rama
`feat/**` o manualmente.

1. Instala Godot 4.4.1 y las plantillas web, verificando el SHA512 oficial.
2. `godot --headless --import` → `tools/ci/check_log.sh` falla si hay errores
   (Godot sin interfaz no siempre devuelve código de error).
3. Prueba de humo: `godot --headless res://tests/smoke/SmokeTest.tscn`.
4. `godot --headless --export-release "Web" build/web/index.html`.
5. `tools/ci/verify_web_build.sh`: archivos, plantilla iPhone, sin hilos,
   marcadores sustituidos, pruebas fuera del paquete y tamaños.
6. Artefactos: `web-build` (la compilación) y `godot-logs` (registros), 14 días.

### Prueba de humo (17 comprobaciones)

- Puente web devuelve cero fuera de la web.
- Las tres escenas registradas existen.
- Inicio → menú principal, con AppState actualizado.
- "Nueva partida" habilitado; "Continuar" y "Ajustes" deshabilitados.
- 10 ciclos Menú → GameShell → Menú sin fallos.
- Las tres pantallas usan `SafeAreaContainer`.
- El margen final = margen base + zona segura.

## Vista previa en Cloudflare Pages (desactivada)

El trabajo `deploy-preview` **no se ejecuta** mientras no se cumplan TODAS estas condiciones:

1. Variable de repositorio `PREVIEW_DEPLOY_ENABLED` = `true`.
2. Entorno `preview` creado, con el Director del Producto como revisor obligatorio.
3. Secretos `CLOUDFLARE_API_TOKEN` y `CLOUDFLARE_ACCOUNT_ID` en ese entorno.
4. Aprobación manual del despliegue en GitHub.

Publica con `wrangler pages deploy` en el proyecto `simulador-presidente`,
como vista previa de la rama (por ejemplo `feat-ui-01.simulador-presidente.pages.dev`).
Nunca se ejecuta para `main`. El repositorio no contiene credenciales.

## Ejecución local (opcional, requiere computadora)

```
godot --headless --export-release "Web" build/web/index.html
```
